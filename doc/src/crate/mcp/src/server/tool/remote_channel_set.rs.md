# remote_channel_set.rs

## fn remote_set
The peer links' system checks each field given before the file is touched, so
a bad value is the caller's `remote::channel::invalid_params`, and
`remote::file` stays the file's own refusal (`crate/peer`'s `system.rs`). A new
remote needs its `cert`, the one field no command can default. The answer is
the row read back from the file, so it shows what the next read sees.

## fn remote_unset
An alias the file lacks is refused rather than ignored, so a typo shows. A live
link keeps running: its keys were read when it opened, and `remote channel
close` ends it.
